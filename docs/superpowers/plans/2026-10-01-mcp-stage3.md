> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

## Review Focus

Inputs the spec implies but the per-task checks must pin; reviewers should attack these first:

1. `timeline_remove_ranges`: ranges that touch clip boundaries, overlap each other, lie partly beyond the end, hit blanks or transitions, span several tracks, or are unsorted; undo of the whole call in one step; markers with ripple.
2. Analysis tools on awkward sources: a file with no audio stream (silence/levels), no video stream (scenes), a source with a space or non-ASCII character in its path, a clip whose range is only part of the file, a clip with a speed change (no timeline mapping), a missing program, a program that exits non-zero.
3. `transcribe` with Whisper not configured, model missing, supplied transcript with overlapping or unsorted segments, and a second call for the same file (cache).
4. Filter tools on a locked track, a blank, a transition, an audio-only clip given a picture filter, a GPU-only service, a duplicate of a filter that forbids duplicates; two consecutive `filter_set` calls must stay two undo steps; undo/redo round trip leaves `get_timeline` identical.
5. `project_set_format` after a clip is loaded or a timeline exists (must refuse and change nothing), odd sizes (must be even), and that the user's saved Video Mode setting is not written.
6. Concurrency: a background job completing while another tool runs, a job outliving a closed project, `get_overview` while an export runs, `wait_ms` at its cap.

```cpp
namespace McpJobs {
QString findProgram(const QString &name);           // applicationDirPath() first, then PATH (QStandardPaths::findExecutable); empty if none
struct Step { QString program; QStringList args; };
struct StepOutput { int exitCode; QByteArray out; QByteArray err; };
struct Record {
    int id = 0; QString kind; QString key;
    QString state = "running";                       // running | succeeded | failed | cancelled
    int percent = -1; QJsonObject result; QString error;
    bool done = false; QElapsedTimer timer; qint64 elapsedMs = 0;
};
using Parser = std::function<bool(const QList<StepOutput> &, QJsonObject &result, QString &error)>;
// Starts the steps one after another in the background. A running record with the same key is returned instead of
// starting another. The result is cached under cacheKey when non-empty and succeeded (see cached()).
std::shared_ptr<Record> run(const QString &kind, const QString &key, const QList<Step> &steps,
                            Parser parse, const QString &cacheKey = QString(), int timeoutMs = 600000);
std::shared_ptr<Record> find(int id);
bool cached(const QString &cacheKey, QJsonObject &result);   // result gains "cached": true
bool waitFor(const std::shared_ptr<Record> &record, int waitMs);   // local event loop, polls 50 ms; true if done
QJsonObject statusJson(const Record &record);       // {job_id,kind,state,percent?,result?,error?,elapsed_ms}
QString cacheKeyFor(const QString &path, const QString &tool, const QString &params); // path|mtime|size|tool|params
}
```

```cpp

QJsonObject trackJson(MultitrackModel &model, int track);
```

- Behaviour: `resolveSource` accepts exactly one of `path` (absolute, existing regular file, not a `:` resource) or both `track` and `clip` (uses `plainClip`; `inSeconds = frame_in / fps`, `outSeconds = (frame_out+1) / fps` with `fps = MLT.profile().fps()`; `speedChanged` when the clip's `warp_speed` property is present and not 1.0). `mapRangeToTimeline` converts source seconds to frames `f = qRound(sec * fps)`, intersects `[frame_in, frame_out+1)`, returns `[{start: clipStart + (a - frame_in), end: clipStart + (b - frame_in)}]` with `end` exclusive, `[]` otherwise.
- `get_job` arguments: `job_id` (non-negative int, required). Unknown id: `textResult("No such job.", true)`. Returns `jsonResult(statusJson)`.
- Records live in a function-static `std::vector<std::shared_ptr<Record>>` (cap 200, oldest done records dropped). Each step runs as a `QProcess` created with `qApp` as parent, merged channels OFF (stdout and stderr both captured), `readyRead` accumulating with an 8 MiB cap per stream (excess dropped, last bytes kept for stderr); `errorOccurred(FailedToStart)` sets `failed` with "Could not start <program>: <reason>"; a `QTimer` per job kills the process at `timeoutMs` ("timed out after N s"). A step with non-zero exit ends the chain as `failed` with the last 2 KB of stderr, unless the parser is given the outputs to judge (parse is invoked only when all steps exit 0, except `ffmpeg` runs whose exit status 0 is required anyway). The parser runs on the GUI thread; the finish path is idempotent (`done` flag) like `ExportRecord`.
- `kind`+`key` dedupe: `run` with a key equal to a running record's key returns that record.

### Task 4: `detect_silence` and `audio_levels`

**Files:** modify `src/mcptools_analysis.cpp`.

**Interfaces:**
- Both take a source via `resolveSource` (`path` XOR `track`+`clip`) plus `wait_ms?` (integer 0..20000, default 0). When the source is a clip, ffmpeg gets `-ss <in_s> -t <dur_s>` BEFORE `-i` so only the clip range is analysed and result times are converted back to SOURCE seconds by adding `in_s`.
- `detect_silence`: `noise_db?` (number -90..-10, default -35), `min_s?` (number 0.05..30, default 0.4). Command: `ffmpeg -hide_banner -nostats -nostdin <seek> -i <path> -vn -af silencedetect=noise=<n>dB:d=<d> -f null -`. Parse STDERR lines `silence_start: <t>` and `silence_end: <t> | silence_duration: <d>`; a start without an end (silence to the end of the analysed range) is closed at the range end (`duration_s` from ffprobe or the clip range). Result `{path, in_s, out_s, ranges:[{start_s,end_s,duration_s, timeline_frames?}], speech_ranges:[{start_s,end_s,duration_s,timeline_frames?}], total_silence_s, cached}`; `speech_ranges` is the complement within `[in_s, out_s]`, dropping segments shorter than 0.01 s; `timeline_frames` is `mapRangeToTimeline(ref, ...)` and only present when the source was given as a clip. A source with no audio stream: tool error "<path> has no audio stream." (check with the `analyze_media` ffprobe path first, cached).
- `audio_levels`: `buckets?` (int 1..600, default 60). Two ffmpeg runs in one chain: (1) `ffmpeg -hide_banner -nostats -nostdin <seek> -i <path> -vn -af ebur128=peak=true -f null -` and parse the Summary block at the end of STDERR: `I:  <x> LUFS`, `LRA:  <x> LU`, `Peak:  <x> dBFS` (true peak); (2) `ffmpeg -nostdin <seek> -i <path> -vn -ac 1 -ar 8000 -f f32le -` decoded to STDOUT and bucketed in C++: for each of `buckets` equal slices compute `rms_db = 20*log10(sqrt(mean(x^2)))` and `peak_db = 20*log10(max|x|)` (floor `-120`). Result `{path, in_s, out_s, integrated_lufs, loudness_range_lu, true_peak_dbtp, buckets:[{start_s,end_s,rms_db,peak_db}], cached}`. Sources longer than 7200 s: error telling the caller to analyse a clip range instead. VERIFY the exact `ebur128` summary text against a real run on `silence.wav` before parsing and record it in the ledger.
- Cache keys: `McpJobs::cacheKeyFor(path, "silence"|"levels", params)` where params include `in_s,out_s` and the thresholds.

### Task 9: `timeline_remove_ranges`

**Files:** modify `src/mcptools_structure.cpp`. Read `pf-structure.md` section 2 and spec section 4.

**Interface:** `tracks` (array of 1..8 distinct non-negative ints), `ranges` (array of 1..500 objects `{start,end}`, absolute timeline frames, `0 <= start < end`, `end` exclusive), `ripple?` (bool, default true). Algorithm (all in ONE `beginMacro(tr("Remove %n range(s)"))`):
1. Validate every track (`validTrack`, not locked) and every range shape. Sort ranges by `start`, merge overlapping or touching ranges, clamp `end` to the longest listed track's playtime, drop ranges that fall entirely past every track's end (if all are dropped: error "No range lies inside the timeline."). 2. 3. Re-query clip indexes with `clipIndexAtPosition` after every push (stage 2 pattern). On any failure after the macro began: `endMacro()`, `MAIN.undoStack()->undo()`, mark nothing, return an error (all-or-nothing).
Result `{tracks:[trackJson...], removed_frames:{"<track>":n,...}, ranges_applied:[{start,end}...]}`. Unlisted tracks are untouched (the client lists every track it wants cut).
